# 啄知 AI 甲方开发阶段审核报告

> 截至 2026-11-06；本报告记录审核时的工作区状态。其他开发工作仍在进行，后续代码及验证结果可能变化。依据《啄知AI_模块任务拆分与双人分工方案》，当前为开发中的原型，尚不能认定甲方全部任务完成或满足比赛交付标准。

## 1. 当前结论

项目已有 Flutter 客户端、FastAPI/SQLite 后端和部分乙方演示接口，可用于继续开发与局部功能演示。真实教学服务、语音与成果事件联调、Android 构建及真机验收尚需完成。演示返回的内容、提示音、固定对话和样例判分不应描述为真实 AI、语音能力或学习成果。

- 乙方演示桩的 2 项直接调用测试已通过，检查课程隔离及样例作答不改变任务、不产生学习事件。

- Flutter 代理报告最新 `flutter analyze` 无问题、3 项 widget 测试通过、Web 构建成功；这些结果不代表 APK 或真机通过。
- 所有测试、静态分析与构建结果须在最终版本冻结后复跑。测试通过不等于完整覆盖方案中的四个联动场景。

## 4. Android 构建与真机检查

代码包含 Flutter Android 工程，但据 Flutter 代理反馈，当前环境未发现 Android SDK，APK 构建和真机运行未验证。比赛要求 App，Web 预览不能代替 Android 交付。需在配置完整 Flutter、Android SDK、JDK 和构建依赖的环境执行 `flutter analyze`、`flutter test` 和 `flutter build apk`，并在目标 Android 设备安装验证登录、课程、核心页面、网络及权限。

手机中的 `127.0.0.1` 指向手机自身；真机连接后端必须提供设备可访问的服务地址。Android 网络策略、HTTPS 和部署环境需按实际配置验证。当前 Android 工程的 applicationId 仍是 `com.example.zhi_ai`，release 使用 debug 签名，Manifest 允许明文流量；正式分发前需按目标环境调整应用标识、签名与网络安全策略，再核实版本、安装包及比赛提交要求。本报告不假定本地 Web 可用就证明手机可用。

## 5. 必须继续完成的验证

1. 与乙方确认契约，将真实学习快照、课程内容、题目、结果和可信增量事件接入，确认身份与课程隔离；样例应保留明确标记。
2. 用真实或经过双方认可的固定测试数据验证四个联动场景，包括成果事件重复读取、失败重试、事务和游标安全，以及 DDL 修改后保留已完成任务。
3. 补齐真实 TTS、ASR、录音与可复用播放器，验证语音失败时仍能阅读；完善前端四态、文件与任务交互。
4. 在安全部署环境复核身份会话、跨域、HTTPS、数据备份、依赖版本与访问控制；不应将开发态暴露到公网。
5. 冻结版本后复跑后端测试、Flutter 分析/测试、Android 构建并完成真机走查，再更新本报告和交付说明。
