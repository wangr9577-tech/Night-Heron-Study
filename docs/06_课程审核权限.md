# 课程审核权限与本地管理

错题转写、答案确认与简答题评分分开处理。学习者可以校对自己的识别文字；题目标准答案和人工评分由独立审核者确认。审核者必须是该课程成员，而且由持有服务器数据库操作权限的管理员为其明确授权；普通注册、创建课程或担任课程拥有者都不会自动取得审核权限。管理员不应给不可信用户授权。

先启动过新版后端，以初始化数据库权限表。以本机项目根目录为工作目录，将下面示例中的数据库路径、课程 ID 和审核员用户 ID 换成实际值。`ZHI_DB_PATH` 若已设置，必须使用该配置指向的同一数据库；否则默认是 `backend/data/zhi.db`。**不要向公网暴露数据库或这个脚本。**

```powershell
$database = 'D:\软件大赛\Night-Heron-Study-app\backend\data\zhi.db'
$course = '<course_id>'
$reviewer = '<reviewer_user_id>'
.\.venv\Scripts\python.exe scripts\manage_review_permissions.py --database $database grant --course $course --user $reviewer --permission content:write
.\.venv\Scripts\python.exe scripts\manage_review_permissions.py --database $database grant --course $course --user $reviewer --permission assessment:review
.\.venv\Scripts\python.exe scripts\manage_review_permissions.py --database $database list --course $course
```

两种权限各自独立。将 `grant` 替换为 `revoke` 可分别撤销；撤销后下次请求即失效。移除课程成员时，其授权级联删除，重新加入不会自动恢复。授予和撤销记录保存在 `review_permission_audit`，包含系统账户名和时间。脚本要求目标数据库已存在，且审核员必须已是未归档课程的成员。

审核者通过自己的账号访问本课程的待审队列；审核端不可确认或评分自己的学习记录。仅有课程访问权、其他课程的权限或已撤销的权限均不足以审核。独立用户确认错题后才允许生成变式；简答题由审核者给出分数与理由后才更新学习者的掌握证据。相关接口以 `/api/v1/courses/{course_id}` 为前缀：

- `GET /mistakes/review-queue` 和 `POST /mistakes/{id}/confirm`：错题确认，需要 `content:write`。
- `GET /mistakes/{id}/review-original`：独立审核者查看学生上传的错题原件，需要 `content:write`，没有原件时返回 404。
- `GET /assessment/review-queue` 和 `POST /attempts/{id}/grade`：主观题审核，需要 `assessment:review`。

通过出题接口为自己创建的题目只用于自测，作答不形成掌握证据，也不能完成计划任务或获取积分；审核学生错题产生的题目不受此限制。查看自己的题目答案接口会记录为查看解析。此规则从新版之后的作答起生效，不会自动追溯或改写历史数据。

此工具只管理本地部署权限，不替代正式环境中的身份治理、系统账户隔离及审计保护。对于独立嵌入引擎的部署，宿主 A1/A2 的 AccessProvider 应实施至少同等的课程隔离与撤销规则。
